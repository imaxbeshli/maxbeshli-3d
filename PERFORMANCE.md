# Диагностика и оптимизация производительности

Сравнение с preview `5b6b05d`. Основная страница, три раздела и «Обо мне»
проверялись в Chromium с программным WebGL (SwiftShader), в настольном окне
1280×800 и мобильном 390×844. Это диагностика причин нагрузки, а не замер FPS
на физическом телефоне. Сценарии проверяют также другие размеры экранов.

## Найденные причины и исправления

| Причина | Изменение |
| --- | --- |
| HTML 44 950 084 байта, включая base64 видео и музыки | HTML 6 733 540 байт: меньше на 85%. SHOWREEL и музыка вынесены в отдельные файлы с неизменными байтами |
| Скрытый AVTOLAB заранее загружал 6,7 МБ | `preload="none"`; воспроизведение и загрузка при показе. Исходные 60 fps сохранены |
| Первый въезд зависел от ограниченного шага симуляции | 2,4 с по реальному времени, с остановкой часов в скрытой вкладке |
| Главная сцена продолжала рисоваться в скрытой вкладке | Отрисовка и видео остановлены; CSS-анимации приостановлены; возобновление проверено |
| Размытие скалы делало 25 выборок текстуры на пиксель в каждом проходе | Размытие кэшируется один раз; два чтения текстур с интерполяцией при входе |
| Большие экраны и высокая плотность пикселей создавали лишнюю нагрузку | Начальный бюджет: до 2,4 млн пикселей на широком экране, до 1 млн на узком. При устойчивой нагрузке масштаб снижается до 65% с медленным восстановлением |
| Постоянное разрешение дополнительных 3D-сцен | FORMA учитывает размер отображения; уменьшены буферы мягкого тумана и стекла «Обо мне» |
| Включённый основной shadow pass без объектов, отбрасывающих тени | Убран пустой проход; настоящие тени архитектурной демонстрации сохранены |
| Ограниченный шаг времени разделов растягивал их анимации при пропусках кадров | Реальный шаг времени с обнулением при смене видимости; исключены повторные записи одинаковых CSS-смещений |
| Неиспользуемые встроенные фотографии старого раздела сайтов | Удалены из HTML и списка встраивания |

Адаптация разрешения работает только в спокойном состоянии главной сцены:
во время приближения и входа разрешение стабильно. DOM-текст не уменьшается.
Отражение обновляется **каждый кадр** одновременно с лодкой. При пониженном
качестве уменьшается только размер его буфера, без пропуска кадров.

Времена выбранных плиток сохранены: приближение 2 с, вход 2 с, выход 2 с,
отъезд 3 с. На программном GPU завершение может попадать на следующий
доступный кадр; накопления искусственно замедленного времени больше нет.

## Результаты измерений

В отдельных последовательных настольных запусках медианный интервал кадров
главной сцены снизился с 1267 до 600 мс. SwiftShader остаётся слишком медленным
для этой сцены: эти числа показывают снижение вычислительной нагрузки,
но не обещают 60 fps на устройствах. В скрытой вкладке число проходов основного
рендерера за примерно 5 секунд снизилось с 12 до **0**.

В предварительном мобильном прогоне после основных оптимизаций разделы
съёмки, AVTOLAB и Telegram давали медианный интервал около 16,7 мс; FORMA —
16,7 мс с p95 33,3 мс. Изменения разрешения тумана/стекла и отражения внесены
после этого прогона; эти цифры не являются замером их отдельного эффекта.

Готовность основной сцены на настольном программном GPU занимала около
20,7 с до и 22,2 с после: ускорение холодного запуска в этом окружении
**не подтверждено**, несмотря на сокращение HTML. Компиляция WebGL и
программный рендеринг остаются ограничением. На реальных устройствах
нужен отдельный замер с аппаратным ускорением и обычной сетью.

## Воспроизведение

```sh
python3 tools/audit-performance.py --output /tmp/desktop.json
python3 tools/audit-performance.py --mobile --output /tmp/mobile.json
python3 tools/audit-performance.py --home-only --output /tmp/home.json
python3 tools/check-runtime-budget.py
python3 tools/check-camera-motion.py
python3 tools/check-foreground-rock.py --coverage-only
python3 tools/check-film-studio.py
python3 tools/check-web-studio.py
python3 tools/check-web-studio.py --mobile
python3 tools/check-telegram-glass-scroll.py
python3 tools/check-about-motion.py
python3 tools/check-mobile-startup.py
python3 tools/check-lantern-boat.py
```

Не запускать аудит одновременно с другими браузерными тестами: они делят
программный GPU. Функциональные проверки допустимо запускать параллельно.
Тест бюджета дополнительно моделирует 4K-экран, медленные и быстрые кадры,
запрет смены разрешения в переходах и отсутствие ранней загрузки вторичного медиа.

Автономный файл создаётся отдельно:

```sh
python3 tools/build-standalone.py --output /tmp/maxbeshli-offline.html
```

Он включает медиа и занимает около 50,55 МиБ. Публиковать следует лёгкий
`index.html` вместе с `assets`, а не автономный файл.

Все перечисленные функциональные проверки завершились успешно. Дополнительно
проверены синтаксис 15 встроенных скриптов, совпадение встроенных копий
с исходниками и идентичность байтов вынесенного видео/музыки. У размытой
скалы тест не обнаружил просвечивания внутренних пикселей; мягкий край сохранён.

Автономная сборка проверена как единственный документ с запретом дополнительных
сетевых загрузок: вход, SHOWREEL и перемотка, встроенная музыка, AVTOLAB.
Открытие через `file://` не проверено: политика браузера облачной среды запрещает
такую навигацию. Используемый Blob-путь для SHOWREEL сохранён.
